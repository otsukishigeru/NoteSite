# AI時代の要求工学 意識調査（アンケートサイト）

`https://chidouka-lab.com/inoki-ken/` として公開しているアンケートサイト一式です。
URLは従来どおり `/inoki-ken/` を維持しています（ID／SubIDによるアクセス制御も現行方式のままです）。

このサイトの目的は、**AI時代の要求工学に関する各種の意識調査を行い、
要求工学が社会的なニーズに応えるものになるよう作り替えていくこと**にあります。

Vercel でホスティングしており、PHPは使えないため、Node.js（Vercelのサーバーレス関数）＋
静的HTMLで構成しています。


### なぜAPIが1ファイルなのか

Vercel の Hobby プランには、サーバーレス関数の数に上限（12個）があります。
このリポジトリではすでに10個を使っているため、アンケート機能は新しい関数を作らず、
`api/inoki-ken.js` に `action` ベースで集約しています。
**機能を追加するときも、原則としてこのファイルに `action` を足してください。**

## 2. データの置き場所

Vercel の KV（Upstash Redis）を使います。

| キー | 内容 |
|---|---|
| `inoki-ken:users` | ID／SubID の一覧（JSON配列） |
| `inoki-ken:surveys` | アンケートの定義（JSON。設問マスタ） |
| `inoki-ken:ans:<アンケートid>` | 回答（リスト。1件＝1JSON、最大5000件） |

`inoki-ken:surveys` が空のときは `lib/inoki-surveys.js` の初期値が書き込まれます。
以後は KV の内容が正となり、管理画面からの編集がそのまま反映されます。

### Googleスプレッドシート・Dropboxへの集約

回答は KV に保存し、**CSV（UTF-8・BOM付き）として書き出す**方式にしています。

- 管理画面「回答データ」タブ →「CSVを書き出す」
- 各アンケートの集計ページ →「CSVをダウンロード」

書き出したCSVは、Googleスプレッドシートの「ファイル → インポート」や、
Dropbox への保存にそのまま使えます。
サービスアカウントの鍵などを持たずに済むため、運用の手間がかかりません。

## 3. 使い方

### サイトを見る

`https://chidouka-lab.com/inoki-ken/`

ログイン画面が出ます。初期登録は次のとおりです（初回アクセス時に自動で登録されます）。

| 項目 | 値 |
|---|---|
| ID | `kogakuin` |
| SubID | `inoki-ken` |

ログイン状態は `sessionStorage` に保存されます。ブラウザのタブを閉じると解除されます。

### 管理画面

`https://chidouka-lab.com/inoki-ken/admin/`

管理パスワードは、サイト共通の環境変数 `ADMIN_PASSWORD`（Vercelのプロジェクト設定）です。
四つのタブがあります。

| タブ | できること |
|---|---|
| 利用者 | ID／SubID の追加・変更・削除（従来どおり） |
| アンケート | 設問の追加・削除・変更、区分の並べ替え、公開状態の切替、アンケートの新規追加・削除 |
| 回答データ | 回答件数の確認、CSVの書き出し、回答の消去 |
| 定義（JSON） | 定義の直接編集、書き出し、初期値への復帰 |

**「この定義を保存する」を押すまで、変更は公開サイトに反映されません。**

## 4. アンケートの定義（設問マスタ）

一つのアンケートは、次の形をしています。

```jsonc
{
  "id": "re-literacy",              // URLに使う識別子。変えると別物になります
  "title": "要求工学リテラシー実態調査",
  "eyebrow": "RE Literacy",         // カードの英字見出し
  "color": "#2e74b5",               // カードとグラフの色
  "status": "open",                 // open（受付中）／draft（準備中）／closed（受付終了）
  "minutes": 6,                     // 所要時間の目安
  "feedback": "sections",           // 省略可。送信直後に区分ごとの平均を回答者に見せる
  "analysis": "matrix",             // 省略可。matrix（二軸の地図）／gap（立場によるずれ）
  "summary": "一覧に出す一行の要約",
  "purpose": "この調査の目的（方針5）",
  "conditions": ["実施の条件", "…"],
  "policy": "結果の検討方針",
  "sections": [
    {
      "id": "A", "label": "用語・概念の理解度", "color": "#2e74b5",
      "note": "回答者への案内文（省略可）",
      "questions": [
        { "id": "a1", "type": "likert", "text": "…",
          "scale": { "min": 1, "max": 5, "low": "低い側", "high": "高い側" } },
        { "id": "c1", "type": "single", "text": "…",
          "options": [ { "v": "core", "label": "…" } ] },
        { "id": "c2", "type": "multi", "max": 4, "text": "…", "options": [ … ] },
        { "id": "c3", "type": "text", "maxlen": 300, "required": false, "text": "…" }
      ]
    }
  ]
}
```

設問の型は `likert`（段階評価）／`single`（単一選択）／`multi`（複数選択）／`text`（自由記述）の四つです。
`required: false` を付けると任意回答になります。

### 気をつけること

- **設問の `id` を変えると、別の設問として扱われます。** 文言だけを直したいときは `id` を変えないでください。
- 設問を削除しても、それまでの回答は消えません。集計に出なくなるだけです。
- 回答者の負担を抑えるため、記述式は各アンケートで多くても1問、しかも任意にしています。
- `analysis` の二つの型は、次の追加項目を必要とします。
  - `matrix` … `matrix: { x: {sec, label}, y: {sec, label}, items: [...] }`
    二つの区分が同じ数・同じ順序の設問を持つことが前提です。
  - `gap` … `gap: { field, groups: [{label, values}], mid, big }`
    プロフィールの項目でグループを分け、平均の差を出します。

## 5. スプレッドシート型の回答

`surveys/sheet.html` では、CSVの雛形をダウンロードして記入し、貼り戻すことができます。
取り込まれた回答は、画面から入力されたものと**まったく同じ検査**（`cleanEntry`）を通るため、
結果は等価です。

雛形は次の構造です。1〜3行目は取り込みの目印なので、消さないよう案内しています。

| 1列目 | 2列目以降 |
|---|---|
| `key` | `p_pos` `p_field` … `q_a1` `q_a2` …（識別子） |
| `項目` | 人が読むための項目名 |
| `記入方法` | 選択肢の番号や段階の説明 |
| `回答1` 以降 | 実際の記入欄 |

選択式は「選択肢の番号」「選択肢の文言」「内部の値」のいずれでも受け付けます。
複数選択は `｜`（縦棒）などで区切ります。一度に取り込めるのは300行までです。

## 6. 補足資料（概念・仮説・参考）

アンケートの背景にある考え方を置いた、補足のページです。いずれも静的HTMLですので、直接編集してください。

- `concept/index.html` … 三本柱と新実在論の整理
- `hypo/index.html` … 分析の軸と五つの仮説命題（`.prop` の `data-h`・`data-new` 属性を保つと絞り込みが働きます）
- `guide/index.html` … 〈純粋要求定義法〉入門

本格版PDFを差し替えるときは、`assets/pdfs/AIReqThough2.pdf` を**同じファイル名のまま**上書きしてください。
`vercel.json` でこのディレクトリに `no-cache` を設定してあるため、差し替え後すぐに反映されます。

なお「参考」は、本サイトの調査とは独立した資料という位置づけです。
文面を変更する際も、この独立性の明記（ページ冒頭の橙色の囲みと、トップページの該当箇所）は残してください。

よく使う型：

```html
<div class="box">          … 青い囲み
<div class="box warn">     … 橙の囲み（注意）
<div class="box phil">     … 紫の囲み（哲学の話）
<div class="define">       … 中央寄せの定義
```

## 8. 安全性についての注意

このサイトの認証は、**関係者以外がふらっと見ないようにするための簡易的な仕組み**です。

- ID・SubIDはハッシュ化せず、そのままKVに保存されます
- ログイン状態はブラウザの `sessionStorage` によるもので、サーバー側のセッション管理ではありません
- 回答の送信APIはサーバー側で認証していません（画面側のログインで入口を絞っているだけです）。
  いたずらが心配な場合は、`status` を `closed` にして受付を止めるか、回答を消去してください
- ページのHTMLソース自体には本文が含まれているため、ソースを表示すればログインなしに内容を読むこともできます
- 通信は必ず https で行ってください

機密性の高い情報は置かないでください。より強い保護が必要になった場合は、
Vercelの環境で使えるBasic認証や、Vercel Edge Middlewareでのアクセス制御を検討してください。

回答データそのものには、氏名・所属機関名・連絡先を含めていません。
採取するのは、立場・分野・要求工学の学習レベル・プログラミング経験・生成AIの活用経験の五つだけです。
